## 2. Визначення термінів

**«Платформа»** або **«LEX AI»** — програмний продукт «SecondLayer», доступний за адресою legal.org.ua, включаючи API-ендпоінти, MCP-сервери та веб-додаток.

**«API»** (Application Programming Interface) — програмний інтерфейс Платформи, що дозволяє Розробнику інтегрувати функціональність LEX AI у власні програмні продукти через HTTP-запити, MCP-протокол або SSE-з'єднання.

**«API-ключ»** — унікальний ідентифікатор автентифікації (рядок виду `sl_…`), що надається Розробнику для доступу до API.

**«Дозволений ендпоінт»** — адреса API, на якій дозволено використовувати API-ключ. Єдиним Дозволеним ендпоінтом є MCP-сервер Платформи за адресою `https://mcp.legal.org.ua/api/v2/mcp` (протокол MCP, транспорт Streamable HTTP), якщо інше не погоджено з Провайдером у письмовій формі.

**«Дозволені інструменти»** — інструменти (tools) MCP-сервера, які Платформа повертає у відповідь на запит `tools/list` для конкретного облікового запису та API-ключа і які включені до тарифного плану Розробника або погоджені окремою угодою.

**«Відкликаний ключ»** — API-ключ, який деактивовано або відкликано Провайдером чи Розробником, строк дії якого сплив або який замінено новим ключем.

**«SaaS-продукт»** — програмне забезпечення як послуга (Software as a Service), створене Розробником із використанням API Платформи, яке Розробник надає своїм Кінцевим користувачам на комерційній основі.

**«Кінцевий користувач»** — фізична або юридична особа, яка використовує SaaS-продукт Розробника.

**«API-запит»** — одиничне звернення SaaS-продукту до API Платформи.

**«Ліміт запитів»** (Rate Limit) — максимальна кількість API-запитів, дозволена протягом визначеного періоду часу відповідно до обраного тарифного плану.

**«Конкуруючий продукт»** — програмний продукт, основна функціональність якого дублює або замінює основні функції Платформи LEX AI, визначені в п. 4.3 цього Договору.

**«White-label»** — використання функціональності API Платформи у SaaS-продукті Розробника під власним брендом Розробника.

## 4. Допустиме та заборонене використання

4.1. **Допустиме використання.** Розробник має право створювати будь-які SaaS-продукти з використанням API, за винятком Конкуруючих продуктів, визначених у п. 4.3.

4.2. **White-label.** Розробник має право використовувати результати API під власним брендом (white-label) за умови дотримання вимог щодо attribution (розділ 5).

4.3. **Заборонені Конкуруючі продукти.** Розробнику забороняється створювати SaaS-продукти, основна функціональність яких відтворює сукупність таких функцій Платформи:
- AI-аналіз юридичних документів із семантичним пошуком по судовій практиці України;
- комплексний пошук та аналіз українського законодавства;
- перевірка контрагентів у державних реєстрах України (ЄДР, ЄДРСР);
- зберігання юридичних документів у захищеному сховищі з AI-обробкою.

Використання окремих функцій API (наприклад, лише пошук по реєстрах або лише аналіз документів) для побудови спеціалізованих продуктів не є створенням Конкуруючого продукту.

4.4. **Загальні обмеження.** Розробнику забороняється:
- перевищувати встановлені Ліміти запитів;
- здійснювати дії, що порушують стабільність або безпеку API;
- використовувати API для незаконних цілей;
- надавати Кінцевим користувачам прямий доступ до API-ключа;
- використовувати результати API для навчання конкуруючих моделей штучного інтелекту;
- здійснювати масове автоматизоване вивантаження даних (scraping) з метою накопичення баз даних поза межами нормального використання API.

4.5. У разі сумніву щодо допустимості конкретного використання Розробник зобов'язаний звернутися до Провайдера за попереднім узгодженням.

4.6. **Межі доступу за API-ключем. Дозволено:**
- використовувати API-ключ виключно на Дозволеному ендпоінті (`/api/v2/mcp`) із заголовком `Authorization: Bearer <ключ>` або через OAuth-авторизацію облікового запису Розробника;
- викликати лише Дозволені інструменти в межах Лімітів запитів і обраного тарифного плану;
- підключати ключ до власних програмних продуктів Розробника та до MCP-клієнтів (Claude Desktop, Claude Code, Cursor, власні агенти), що працюють від імені Розробника;

4.7. **Межі доступу за API-ключем. Заборонено:**
- використовувати API-ключ на будь-яких інших ендпоінтах Платформи, зокрема `/v1/mcp`, `/v1/sse`, `/sse`, `/api/tools/*`, у службових, внутрішніх та адміністративних інтерфейсах і у веб-додатку, незалежно від того, чи приймає такий ендпоінт ключ технічно;
- викликати або намагатися викликати інструменти, що не є Дозволеними, зокрема інструменти імпорту даних, адміністрування, масового завантаження та пошуку облікових даних (OSINT), а також обходити відмову Платформи (відповіді з кодами `TOOL_FORBIDDEN`, `API_KEY_V2_ONLY`);

- передавати ключ третім особам чи Кінцевим користувачам, публікувати його у відкритому коді, вставляти у сторонні сервіси, що зберігають або виконують код (онлайн-пісочниці, чат-боти, спільні блокноти), або використовувати один ключ для кількох незалежних продуктів чи замовників;
- створювати додаткові облікові записи чи ключі з метою обходу Лімітів запитів або інших обмежень;
- використовувати результати, отримані через API, для систематичного копіювання баз даних Платформи.

4.8. **Журналювання.** Усі запити з використанням API-ключа журналюються Провайдером (час, ендпоінт, інструмент, IP-адреса, клієнтське програмне забезпечення, обсяг відповіді, результат автентифікації). Журнал є належним доказом факту та обсягу порушення меж доступу.

5.1. **Обов'язковий attribution.** Розробник зобов'язаний розмістити у своєму SaaS-продукті помітне маркування **«Powered by LEX AI»** або **«Працює на LEX AI»** у кожному місці, де Кінцевому користувачу відображаються результати, отримані через API Платформи.

5.2. **Вимоги до розміщення.** Маркування attribution має бути:
- візуально помітним та читабельним;

5.3. **Логотип.** Провайдер надає Розробнику набір офіційних логотипів та brand guidelines для використання attribution. Розробник зобов'язується не модифікувати логотип Провайдера.

5.4. **White-label виняток.** Для white-label рішень допускається зменшений attribution у форматі текстового посилання у підвалі інтерфейсу. Повне видалення attribution можливе лише за окремою письмовою угодою з Провайдером та може передбачати додаткову плату.

5.5. **Заборона введення в оману.** Розробник не має права:

## 7. Рівень обслуговування (SLA)

7.1. **Доступність API.** Провайдер гарантує доступність API на рівні **99,9%** (дев'яносто дев'ять і дев'ять десятих відсотка) протягом кожного календарного місяця, що відповідає не більше ніж 43 хвилинам простою на місяць.

7.2. **Розрахунок доступності.** Доступність розраховується як:

```
Доступність = (Загальна кількість хвилин у місяці − Хвилини простою) / Загальна кількість хвилин у місяці × 100%
```

7.3. **Виключення з розрахунку простою.** Не враховуються як простій:
- планові технічні роботи, про які Провайдер повідомив за 48 годин (не більше 4 годин на місяць);
- простої, спричинені діями Розробника або його Кінцевих користувачів;
- обставини непереборної сили (розділ 13);
- простої зовнішніх сервісів, від яких залежить API (OpenAI, AWS, тощо).

7.4. **Компенсація за порушення SLA.** У разі порушення гарантованого рівня доступності Розробник має право на компенсацію у вигляді кредиту на балансі:

| Фактична доступність | Кредит (% від місячної оплати) |
|---|---|
| 99,0% — 99,9% | 10% |
| 95,0% — 99,0% | 25% |
| менше 95,0% | 50% |

7.5. **Порядок отримання компенсації.** Розробник подає запит на компенсацію протягом 10 робочих днів після закінчення календарного місяця, в якому відбулось порушення SLA. Кредит зараховується на баланс протягом 5 робочих днів.

7.6. **Максимальна компенсація.** Сукупна компенсація за порушення SLA за один календарний місяць не може перевищувати 50% від суми, витраченої Розробником на API-запити за цей місяць.

7.7. **Час відгуку API.** Провайдер докладає комерційно обґрунтованих зусиль для забезпечення часу відгуку API:
